## 自动更新密钥

发布更新使用独立的密码保护签名密钥：

- Actions secret `TAURI_SIGNING_PRIVATE_KEY`
- Actions secret `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
- Actions variable `TAURI_UPDATER_PUBKEY`

普通开发和 PR 构建不会生成 updater 包。版本 tag 会先验证这三项配置，再生成 updater 产物及其 Minisign 签名；汇总 release 前还会用注入的公钥逐个验证最终 `.sig` 与 artifact，不能用“变量非空”替代密钥配对检查。私钥不能提交到仓库，丢失后旧版本无法验证新更新包。这里的 Minisign 与 Apple Developer ID 是两套独立机制。

stable 构建访问 GitHub 的 latest stable release。`X.Y.Z-canary.N` 构建访问 `updater-feed` 分支上的 `channels/canary.json`；canary 草稿手动发布后，`.github/workflows/publish-canary-updater-feed.yaml` 才会重新下载已发布 artifact、验签并推进 feed，draft 不会提前暴露。feed 拒绝回退到更低 canary 版本。

## 发布前人工 smoke test

1. macOS：播放、暂停、切歌、喜欢、托盘、Dock、关闭窗口、Discord、代理和应用内更新。
2. Ubuntu：`playerctl` 双向控制、OSDLyrics、托盘、三种关闭策略、代理和 updater 包启动。
3. Windows：托盘、三种关闭策略、全局快捷键、代理和 updater 包启动。
4. Touch Bar：在真实硬件上验证全部 8 个按钮及动态图标。
